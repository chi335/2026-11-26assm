## 1. 컴퓨터 기초 및 메모리 공간 구조 (01~08)

### 01. 기계어와 어셈블리 개념
* **기계어 (Machine Code):** CPU가 직접 실행 가능한 $0$과 $1$의 이진 데이터 형태의 언어입니다.
* **어셈블리어 (Assembly Language):** 기계어 비트 패턴에 1:1로 대응되는 문자 기호(Mnemonic, 예: `MOV`, `ADD`)를 부여한 저급 언어입니다.
* **어셈블러 (Assembler):** 작성한 어셈블리 코드를 기계어로 번역하는 도구입니다.

### 02. 폰 노이만 구조 이해
* **내장 프로그램 방식 (Stored-Program Concept):** 명령어와 데이터를 구별하지 않고 동일한 메모리 공간에 저장하여 실행하는 현대 컴퓨터의 기본 구조입니다.
* **주요 구성 요소:** CPU(ALU, 제어장치, 레지스터), 메모리(주기억장치), 입출력 장치(I/O).
* **폰 노이만 병목 현상:** CPU와 메모리 간 버스 전송 속도의 한계로 발생하는 성능 병목 현상입니다.

### 03. 개발 환경과 도구 흐름
소스 코드가 실행 파일이 되는 Toolchain 과정:
$$\text{소스 코드 (.c/.asm)} \xrightarrow{\text{컴파일러}} \text{어셈블리 코드 (.s)} \xrightarrow{\text{어셈블러}} \text{목적 파일 (.o)} \xrightarrow{\text{링커}} \text{실행 파일 (.exe)}$$

### 04. 진법 변환과 수 체계
* **16진법 (Hexadecimal):** 2진법 4비트를 1글자($0 \sim \text{F}$)로 표현하여 저급 프로그래밍에서 직관적 데이터 표현에 사용됩니다.
* **$2$의 보수 ($2$'s Complement):** 컴퓨터는 뺄셈을 감산기 없이 $2$의 보수 연산을 통해 덧셈으로 처리합니다.

### 05. 문자와 타입의 메모리 표현
* **문자 인코딩:** ASCII ($1\text{ Byte}$), Unicode/UTF-8 (가변/고정 인코딩).
* **바이트 저장 순서 (Endianness):**
  * **리틀 엔디안 (Little-Endian):** 하위 바이트를 메모리의 낮은 주소에 저장 (x86/x64 아키텍처 기본).
  * **빅 엔디안 (Big-Endian):** 상위 바이트를 메모리의 낮은 주소에 저장 (네트워크 프로토콜 표준).

### 06. 메모리 공간의 기본 구조
프로세스가 OS로부터 할당받는 가상 메모리 레이아웃:

| 영역 (Segment) | 설명 | 특징 |
| :--- | :--- | :--- |
| **Code (Text)** | 실행할 기계어 명령어가 저장되는 영역 | 읽기 전용 (Read-Only) |
| **Data / BSS** | 전역 변수 및 정적(static) 변수 저장 | Data: 초기화됨 / BSS: 초기화 안 됨 |
| **Heap** | 프로그래머가 동적으로 할당하는 영역 | 낮은 주소 $\rightarrow$ 높은 주소로 증가 |
| **Stack** | 지역 변수, 매개변수, 리턴 주소 저장 | 높은 주소 $\rightarrow$ 낮은 주소로 감소 (LIFO) |

### 07. 레지스터의 역할과 분류 (x86-64 기준)
* **범용 레지스터:** `RAX` (산술/반환값), `RBX` (베이스 주소), `RCX` (카운터), `RDX` (데이터 보조)
* **특수 목적 레지스터:**
  * `RIP`: 다음 실행할 명령어 주소 (Instruction Pointer)
  * `RSP`: 스택 최상단 주소 (Stack Pointer)
  * `RBP`: 현재 스택 프레임의 기준 주소 (Base Pointer)
  * `RFLAGS`: 연산 결과 상태 플래그 저장

### 08. 데이터 이동 명령 이해
* `MOV dest, src`: `src` 값을 `dest`로 복사 (메모리 $\rightarrow$ 메모리 직접 복사 불가).
* `LEA dest, src`: 메모리에 저장된 값이 아닌 계산된 **주소 값 자체**를 로드.
* `PUSH src` / `POP dest`: 스택 포인터를 조절하며 데이터를 스택에 삽입/추출.

## 2. 산술 연산 및 주소 지정 방식 (09~12)

### 09. 산술 명령과 플래그
* **명령어:** `ADD`, `SUB`, `INC`, `DEC`, `NEG`, `MUL`, `DIV`
* **주요 상태 플래그 (EFLAGS):**
  * `ZF` (Zero Flag): 연산 결과가 $0$일 때 1
  * `SF` (Sign Flag): 연산 결과가 음수일 때 1
  * `CF` (Carry Flag): 무부호(Unsigned) 연산 시 올림/빌림 발생 1
  * `OF` (Overflow Flag): 부호 있는(Signed) 연산 시 표현 범위 초과 1

### 10. 명령어 구조와 오퍼랜드
* **명령어 구조:** $\text{Opcode (연산자)} + \text{Operand(s) (피연산자)}$
* **오퍼랜드 종류:** 즉시값(Immediate), 레지스터(Register), 메모리(Memory)
* **규칙:** 두 피연산자의 크기가 일치해야 하며, 메모리 간 직접 이동은 불가능합니다.

### 11 & 12. 주소 지정 방식 (Addressing Modes)
* **즉시 주소지정:** `MOV EAX, 10` (상수 직접 지정)
* **레지스터 주소지정:** `MOV EAX, EBX` (레지스터 값 활용)
* **직접 주소지정:** `MOV EAX, [0x401000]` (절대 메모리 주소 지정)
* **간접 주소지정:** `MOV EAX, [EBX]` (레지스터가 가진 주소 참조)
* **기반 변위 주소지정:** `MOV EAX, [EBP - 4]` (지역 변수 접근)
* **유효 주소 (Effective Address) 계산 공식:**
  $$\text{Effective Address} = \text{Base Register} + (\text{Index Register} \times \text{Scale}) + \text{Displacement}$$

## 3. 제어 흐름과 코드 변환 (13~21)

### 13 & 14. 비교 명령과 조건 분기
* `CMP op1, op2`: `op1 - op2` 뺄셈 연산 후 결과는 버리고 플래그만 변경.
* `TEST op1, op2`: `op1 AND op2` 비트 연산 후 플래그만 변경 (레지스터 $0$ 검사 등에 활용).
* **분기 명령어 (`Jcc`):**
  * 부호 없음: `JA` ($>$), `JAE` ($\ge$), `JB` ($<$), `JBE` ($\le$)
  * 부호 있음: `JG` ($>$), `JGE` ($\ge$), `JL` ($<$), `JLE` ($\le$)
  * 동등 여부: `JE` ($=$), `JNE` ($\ne$)

### 15. 다중 분기 구현 (Switch-Case)
* **If-Else 체인:** 조건이 불연속적이거나 적을 때 순차 비교.
* **점프 테이블 (Jump Table):** 조건이 연속적일 때 이동 주소 배열을 만들어 $O(1)$ 속도로 분기 (`JMP [JumpTable + EAX * 4]`).

### 16 ~ 18. 루프 구조와 중첩 루프 제어
* **`LOOP` 명령어:** `ECX`를 $1$ 감소시키고, `ECX != 0` 이면 지정 라벨로 점프.
* **루프 변환 구조:** C언어의 `while`문은 하단 검사 방식(`do-while` 형태)으로 반전(Loop Inversion) 변환되어 분기 오버헤드를 줄입니다.
* **중첩 루프:** 바깥쪽 루프의 `ECX` 값이 덮어씌워지지 않도록 안쪽 루프 진입 전 `PUSH ECX`, 종료 후 `POP ECX` 수행.

### 19 & 20. C언어 산술식 및 조건문 변환
* **비트 시프트 연산:** $2^n$ 곱셈/나눗셈은 `MUL`/`DIV` 대신 빠른 `SHL`/`SHR` 명령어 사용.
* **조건문 변환 규칙:** C언어 조건의 **"반대 조건"**에 맞추어 Skip 점프를 수행하도록 변환.
  ```assembly
  ; if (a > b) x = 1;
  CMP a, b
  JLE L_SKIP    ; a <= b 이면 건너뜀 (반대 조건)
  MOV x, 1
  L_SKIP:
  ```

## 4. 함수 호출 규약 및 메모리 배치 (22~30)

### 22. 호출 규약 (Calling Convention)

| 호출 규약 | 인자 전달 순서 | 스택 정리 주체 | 주요 용도 |
| :--- | :---: | :---: | :--- |
| **`cdecl`** | 오른쪽 $\rightarrow$ 왼쪽 (Stack) | **호출자 (Caller)** | C/C++ 기본 (가변 인자 지원) |
| **`stdcall`** | 오른쪽 $\rightarrow$ 왼쪽 (Stack) | **피호출자 (Callee)** | Windows API 표준 |
| **`fastcall`** | 레지스터(`ECX`, `EDX`) + Stack | **피호출자 (Callee)** | 빠른 함수 호출 목적 |
| **`x64 ABI`** | 레지스터(`RCX`, `RDX`, `R8`, `R9`) + Stack | **호출자 (Caller)** | 64비트 OS 표준 |

* **반환값:** 정수/포인터 반환값은 `EAX` / `RAX` 레지스터를 통해 전달.

### 23. 스택 프레임 (Stack Frame) 구조
함수 호출 시 스택에 생성되는 메모리 영역:
1. **프롤로그 (Prologue):**
   ```assembly
   PUSH RBP          ; 이전 베이스 포인터 보존
   MOV RBP, RSP      ; 현재 스택 상단을 새로운 베이스로 설정
   SUB RSP, N        ; 지역 변수 공간 할당
   ```
2. **에필로그 (Epilogue):**
   ```assembly
   MOV RSP, RBP      ; 지역 변수 공간 해제 (또는 LEAVE)
   POP RBP           ; 이전 베이스 포인터 복원
   RET               ; 스택에 저장된 반환 주소로 복귀
   ```

### 24 ~ 27. 배열, 포인터, 구조체 메모리 배치
* **배열:** 1차원 및 2차원(행 우선) 배열은 메모리에 **연속적인 1차원 공간**으로 배치됩니다.
  $$\text{Address}(A[i][j]) = \text{Base Address} + (i \times M + j) \times \text{Element Size}$$
* **포인터 연산:** 포인터에 $+1$을 할 경우 실제 주소는 가리키는 타입의 크기(`sizeof(T)`)만큼 증가합니다.
* **구조체 데이터 정렬 (Alignment):** CPU 접근 효율성을 위해 $N$바이트 데이터는 $N$의 배수 주소에 위치하며, 멤버 사이에 패딩(Padding) 바이트가 삽입됩니다.

### 28 ~ 30. 문자열 처리 및 시스템 콜 (Syscall)
* **C-String:** 널 문자(`'\0'`, `0x00`)로 종료되는 문자열.
* **스트링 명령어:** `MOVS`(복사), `CMPS`(비교), `SCAS`(탐색), `STOS`(초기화) + `REP` 프레픽스로 연속 처리.
* **시스템 콜 (System Call):** 유저 모드에서 커널 서비스를 요청하는 통로 (x86: `int 0x80` / x64: `syscall`).

## 5. 디버깅, 최적화 및 동적 메모리 (31~38)

### 31 & 32. 디버거 제어 및 콜 스택 분석
* **디버그 제어:** Breakpoint(`INT 3`), Step Into(`F11`), Step Over(`F10`), Continue(`F5`).
* **콜 스택 역추적 (Unwinding):** 크래시 발생 시 `RBP` 체인을 타고 올라가 어떤 함수 호출 경로를 거쳐 에러가 발생했는지 역추적합니다.

### 33. 오류 추적의 기본 절차
* **Segment Fault / Access Violation (`0xC0000005`):** 유효하지 않은 메모리 접근.
* **추적 순서:** 버그 재현 $\rightarrow$ 크래시 지점(`RIP`) 확인 $\rightarrow$ 레지스터/스택 검사 $\rightarrow$ 원인 파악 및 수정.

### 36. 메모리 접근 최소화 (최적화)
* **속도 차이:** $\text{Register (0.5ns)} \gg \text{Cache} \gg \text{RAM (50~100ns)}$
* **기법:** 루프 내부 변수를 레지스터에 상주(Register Caching)시키고, 메모리 순차 접근을 통해 캐시 적중률(Cache Hit Ratio)을 높임.

### 37. 동적 메모리 (Heap) 분석
* **함수:** `malloc()` / `free()`, `HeapAlloc()` / `HeapFree()`
* **주요 저급 버그:**
  * **Memory Leak:** 해제되지 않고 남아있는 힙 메모리.
  * **Use-After-Free (UAF) / Double Free:** 이미 해제된 힙 포인터를 다시 참조하거나 중복 해제하여 보안 취약점 유발.

### 38. 복합 분기와 오류 처리 패턴
* **가드 클로저 (Early Exit):** 예외 조건을 상단에서 검사해 빠르게 탈출(`JMP Error`).
* **공통 해제 (Cleanup) 패턴:** 오류 발생 시 동적 메모리 및 자원 누수를 방지하기 위해 공통 라벨(`cleanup:`)로 이동 후 리턴.
